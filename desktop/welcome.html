Recruence

How do you want to run Recruence?

Recruence has two parts: this app, where you manage jobs, candidates and interviews, and a backend that takes applications, runs the interviews and writes the reports. Choose where the backend runs. You can change this later in Settings → System.

Bring your own cloud Recommended

Run the backend on your own cloud server, with your own database. Recruence keeps working around the clock: candidates apply, take their interviews and get evaluated even when this computer is off.

AWSGoogle CloudAzure DigitalOceanHetznerRailway
  • Your server, your database (PostgreSQL, such as Neon): your candidates' data stays in your accounts.
  • One permanent https:// address for candidate links, MeetStream and your careers website.
  • Everyone on your team signs in from their own copy of this app.

Don't have a server yet? How to set one up
  1. A database: create a PostgreSQL database (Neon, Supabase, Amazon RDS, Cloud SQL, Azure Database for PostgreSQL…) and copy its connection string.
  2. A server: run the Recruence server image (the project's Dockerfile) on your cloud, as one copy that's always on, with REMOTE_DASHBOARD=true, DATABASE_URL, SETTINGS_ENCRYPTION_KEY and PUBLIC_BASE_URL (the guide docs/CLOUD.md and deploy/cloud/ have everything).
  3. HTTPS: give it a permanent https:// address on your domain: the platform's own, Caddy, or a Cloudflare Tunnel.
  4. Connect: paste that address above. The first account of a new database is created on the server itself; after that, everyone signs in here.

Run on this computer

The backend runs inside this app. Good for trying Recruence, or one recruiter.

  • Nothing to set up: start now.
  • Interviews and applications only work while this computer is on and Recruence is open.
  • Candidates and MeetStream reach it through a tunnel to this computer.

You can move to your own cloud later: your data comes with you when it's in a hosted database.
